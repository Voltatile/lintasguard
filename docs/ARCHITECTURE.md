See README.md sections 4 to 8 for the design. This file records deeper notes.

| 2026-11-20 | Mode manager: island sensor lost requires level 3 (level 4 without timetable info) | The gate cannot be cleared by the island, so a guard or timetable is needed. Safer side. |
| 2026-11-20 | Mode manager: a RESTARTING or DEAD sensor driver counts as a lost sensor | Both drivers of a direction restarting at once must not be treated as one healthy sensor. |
| 2026-11-20 | Mode manager: health/schedule/plant process DEAD or RESTARTING gives level 2; bridge gives level 1; battery FAILED gives level 2 | README 8.5 says "level 2, 3 or 4 depending on the process" without a table. Bridge has no safety role. |
| 2026-11-20 | Level 4 release needs a `guard_ack` given while the required level is <= 1, then stable for `T_stable`; an ack given while unhealthy is void, and a pending ack is voided when the required level rises above 1 or level 4 is re-entered. (Revised after the review: the first version kept an ack given during a fault, which let level 4 release by itself later.) | README 3.1: "guard-ack and healthy sensors" and "never returns on its own". The guard attests to the state they see; the cost of a rejected ack is one more `lgctl` command. A WARNING-level component is still functional, so it does not block the release. |
| 2026-11-20 | De-escalation goes straight to the required level after `T_stable` of an unchanged requirement | README diagram shows single steps; this is the stricter hysteresis (any change restarts the timer) and is simpler to verify. |
| 2026-11-20 | Boot lock: released by all-healthy (required level 0) for `T_boot_stable`, no guard needed; a valid guard ack (required level <= 1) can also release it. A real level 4 event during boot (self check, controller/supervisor/gate DEAD, gate FAILED) removes the boot lock. A single failed sensor (level 2) keeps boot locked. | README 8.6 describes only the all-healthy path. Without the last rule a boot-time fault would be released without a guard, which README 3.1 forbids. "No information yet" and sensor faults at boot are not hard events. |
| 2026-11-20 | Metrics: "total closure" counts time the gate is not UP; "closure per train" is DOWN until the gate starts rising; boot DOWN period is counted as blocked time but not as a train closure | Road users are blocked while the gate lowers and raises too; per-train closure follows README 8.7 literally. |
| 2026-11-20 | Wrong side counts any gate state other than DOWN (LOWERING, RAISING, FAULT, UP) while a train is on the island | Strictest reading of README 8.7 ("gate is not DOWN"). |
| 2026-11-20 | Unknown enum values fail closed: verdict not OK/WARNING = FAILED, proc state not RUNNING/RESTARTING = DEAD, clearing level > 4 = level 4 | Inputs arrive in IPC messages; an out-of-range value must never read as healthy. |
| 2026-11-20 | Elapsed time uses `lg_elapsed_ge`: a timestamp in the future is "not elapsed" | `lg-gate` timestamps can be a few ms newer than the `now_ms` read at the start of a tick; plain unsigned subtraction would read that as a huge elapsed time and satisfy the minimum down time. |
| 2026-11-20 | Gate clearing needs an island sighting in level 3 and whenever axle counting is not healthy | Otherwise "island clear" can be true before the train has arrived. Trade-off: a false activation with an unhealthy axle counter keeps the gate down until a guard confirms (right-side, safer). Same-direction approach is not an input yet; to be revisited in Step 7. |
| 2026-11-20 | In level 3 a guard confirmation replaces the island condition only, not a healthy axle counter | If the axle counter is healthy and says in != out, wagons may still be on the crossing. |
| 2026-11-20 | Extra pre-warning margin applies in level 2 and above | A direction with working sensors in level 3 still has reduced redundancy elsewhere; the margin is the safer choice. |
| 2026-11-20 | `schedule_ok` must be 0 until `lg-schedule` reports usable information; `LG_T_INFO_TIMEOUT_MS` is applied by the controller or `lg-schedule` (Step 12), the mode manager only sees the debounced flag | Mode manager has no clock source for information age. README 8.4 timeout is not implemented in Step 4. |
| 2026-11-20 | Not covered by the mode manager inputs yet: sample freshness at boot (README 8.6 "valid samples") | Relies on the health verdict until Step 7 adds a freshness input. |
| 2026-11-20 | Protocol v2: message types start at `LG_MSG_BASE = 0x1000` (was 1 to 10) | QNX reserves 0x000 to 0x1FF (`_IO_MAX` in `sys/iomsg.h`); `message_attach` only takes types above it, and `name_open` itself sends `_IO_CONNECT`. No sender or receiver existed yet. |
| 2026-11-20 | Reply to `LG_MSG_GATE_CMD` is `lg_gate_state_msg_t`; an invalid command is rejected with `MsgError(EINVAL)`; `lg_ack_t` is not used by the gate | The controller needs the state in the answer; no new message type was needed. |
| 2026-11-20 | Watchdog keepalive = any valid `GATE_CMD` or an `LG_PULSE_HEARTBEAT` pulse. It trips when the controller wants the gate up (target UP) and nothing arrived for more than `LG_GATE_WATCHDOG_MS` (100 ms). Checked once per 10 ms tick, so the gate starts lowering 100 to 110 ms after the last keepalive | README 8.5: "missing commands and heartbeats". Resolution is the tick period and is stated, not hidden. The gate measures the silence itself when it trips (`evidence/step05_gate.txt`: 109 ms in the recorded run, against the 100 ms limit). The time from `kill -9` to the trip was not measured; it is shorter than the silence because the client's last heartbeat is up to 50 ms older than the kill. |
| 2026-11-20 | After a watchdog trip the gate stays DOWN until the controller sends RAISE again | Never reopen on its own after a controller failure. |
| 2026-11-20 | `lg-gate` serves from one thread and one dispatch (resource manager, name, message, pulses, timer) on a channel created with `_NTO_CHF_FIXED_PRIORITY | _NTO_CHF_UNBLOCK | _NTO_CHF_DISCONNECT` | Measured (`evidence/step05_priority.txt`): on a default channel the server thread adopts the sender's priority, even a lower one. Trade-off: no priority inheritance from a higher-priority client (controller 50 over gate 48); accepted because nothing runs between 48 and 50 except the supervisor, and it must be revisited if priorities change. |
| 2026-11-20 | `io_write` on `/dev/lg/gate` is an explicit handler returning `EPERM` | The default handler accepts and discards the data, which looks like success. Found by the target test. |
| 2026-11-20 | Target builds use `-D_QNX_SOURCE` next to `-std=c11 -Wall -Wextra -Werror` | Strict `-std=c11` hides the POSIX/QNX declarations in the SDP headers (`clock_gettime`, `SETIOV`, the OCB type). |
| 2026-11-20 | Initial values: `LG_GATE_TRAVEL_MS` 4000, moving current 800 mA, holding current 50 mA, fault timeout 3x nominal | Placeholders (marked "initial" in `lg_config.h`), to be tuned with the health model in Step 11. A movement slower than 3x nominal is reported as FAULT but still completes. |
| 2026-11-20 | Gate model: a watchdog trip starts the lowering from "now"; time before the trip is not counted as travel | Found by a failing unit test and a target run (lowering took 3988 ms instead of 4000). When the trip happens mid-raise, at most one tick of upward motion is not credited. |
| 2026-11-20 | `/dev/lg/gate` mode is 0644 and `devctl` fault injection is NOT yet restricted to authorised callers; the test client plays the controller | Credential checks (only the controller may command the gate; fault injection only for privileged callers) are Step 13. Until then the gate must not be exposed outside the VM. |
| 2026-11-20 | Deviation from the Step 5 plan: no `--exit-silent` option in `lg-gate-test`; the test starts a client that holds with heartbeats and `kill -9`s it | It is the exact check in the README ("killing the client triggers the watchdog") and needs no special flag. |
| 2026-11-20 | `scripts/deploy.sh` kills running copies by PID from `pidin`, waits, copies, then `chmod +x` | `slay` only matches the name as the process was started; a running binary cannot be overwritten; `scp` from Windows drops the execute bit. |
| 2026-11-20 | Gate model: `set_fault` no longer resets the movement timer. `travel_ms` measures from the movement request; the FAULT timeout restarts only when the fault actually changes; the fixed-point remainder is rescaled to the new effective travel time (not dropped, not left stale) | The `tester` agent showed the first version made `last_travel_ms` and the FAULT timer misleading, and could stop a very slow gate completely when the same fault was re-sent every millisecond. Leaving the remainder unscaled made the position jump (256 failures in a unit test), so it is rescaled. |
| 2026-11-20 | Gate model: watchdog compares with "strictly more than" through its own wrap-safe helper (no `+ 1` that overflows); the gate current is clamped to 32 bits; `travel_ms` 0 is raised to 1 and above 1,000,000 ms is clamped; fault timeout factor 0 is raised to 1 | Findings from the `tester` agent for extreme configurations. All are in the safe direction (the gate lowers, nothing divides by zero, no overflow). |
| 2026-11-20 | Gate model requires a non-decreasing clock: a step with an older timestamp is ignored completely, watchdog included, until the clock catches up. Documented in `lg_gate_model.h` | CLOCK_MONOTONIC never goes back. A caller that cannot guarantee that must not use the model. Gaps above 2^31 ms (24 days) between steps are also out of range. |
| 2026-11-20 | Any valid `GATE_CMD`, including lights and bell commands, feeds the watchdog | A controller that is alive keeps all its commands flowing; a dead controller sends nothing. To be revisited in Step 7 if the controller sends lights commands from a different thread than the gate tick. |
| 2026-11-20 | Open: the `LG_PULSE_HEARTBEAT` keepalive is accepted from ANY connection to `lg/gate`. A live process that is not the controller could keep a gate UP after the controller died | Found in the Step 5 review. Step 13 must identify the sender of pulses too (the `scoid` in the pulse, then `ConnectClientInfo`), not only the senders of `GATE_CMD` and devctl. |
| 2026-11-20 | `devctl` fault injection needs a descriptor opened for writing and a message long enough for its data (`ctp->info.msglen` is checked, not only the client-supplied `nbytes`) | Review finding: a read-only descriptor could set STUCK_UP (gate cannot lower, also not on a watchdog trip) or CRASH. Authentication proper is still Step 13. |
| 2026-11-20 | `lg-gate` logs to stderr only while starting up; once the dispatch loop runs, logging goes to slog2 only | A write to a stuck terminal or pipe would block the single thread that also runs the watchdog (CLAUDE.md section 6). The watchdog trip itself is logged to slog2. |
| 2026-11-20 | A failed `clock_gettime` makes `lg-gate` abort (a restart boots DOWN) | The model ignores a clock that stands still, which would freeze the watchdog silently. Failing to the safe state follows CLAUDE.md section 6. |
| 2026-11-20 | `/dev/lg/gate` text is regenerated on every read; read it with one read (as `cat` does) | A shared snapshot mixed two states when two readers interleaved. A reader that reads in small pieces can still see a line that changed between its reads. A per-open buffer needs a custom OCB and is left for later. |
| 2026-11-20 | `deadline_ms` in `GATE_CMD` (README 7.2) is accepted but ignored; the FAULT state uses 3 times nominal travel instead | Not needed for Step 5. Decide in Step 7 whether the controller needs it. |
| 2026-11-20 | `LG_MSG_GATE_STATE` is only sent as the reply to `GATE_CMD`; there is no status query and no unsolicited report (README 4.3 step 4, 7.2) | To be decided before Step 7. The controller can repeat `GATE_CMD` every tick and read the state from each reply. |
| 2026-11-20 | Makefile: binaries and host tests depend on all headers; compiler inputs are the `.c` prerequisites only | After the protocol bump a header change could leave stale objects. |
| 2026-11-20 | Protocol v3: `LG_MSG_TRUTH_QUERY` and `LG_MSG_TRUTH_REPLY` (sensor to plant) | The sensors need the ground truth from the plant process; only they ask for it, the controller never sees it (README 4.2). |
| 2026-11-20 | Approach sensors are direction aware: a sensor of side S sees only trains travelling from S toward the island. Island sensors see any train on the island | Otherwise the far approach sensors would see a train that has already crossed, and the controller would close the gate again for a train that is moving away. A single track used in both directions would need a different rule. |
| 2026-11-20 | The model has one track per direction (double track); trains of one direction must not overlap, trains of different directions are independent | Keeps the plant simple and the scenarios checkable. The scenario loader refuses overlapping same-direction trains. |
| 2026-11-20 | Axle counts: an approach sensor counts the axles of trains from its side that passed its point; the island sensor of side S counts the axles of trains from S that have left the island | Matches README 8.2 "axle count in equals axle count out" with one number per sensor. |
| 2026-11-20 | Sequence numbers count ticks, not sent samples: a dropped sample or a failed send consumes a number | The receiver can see losses as gaps (README 8.3). Measured in the recorded run: dropout 50 percent gave 175 gaps, a 3 s hang gave 368 gaps in the sink. |
| 2026-11-20 | A sensor that gets no truth from the plant reports quality 0, occupied 0, and counts `plant_fail`; HANG overrides this (no sample at all). `lg_vsensor_usable` (voting) requires quality >= 1, so such a sensor is never used for activation or clearing | Found in the Step 6 review: without the quality rule a blind island sensor would count as a clear track until the health monitor exists (Step 11). Reporting occupied 1 instead would close the road for a simulation artefact. Until Step 11 the controller must treat quality 0 as FAILED. |
| 2026-11-20 | HANG stops the samples but keeps the device answering; CRASH aborts the process | HANG must be inspectable and clearable from the shell; the supervisor restart is Step 8. |
| 2026-11-20 | Raw level model: clear 200, occupied 800, threshold 500, noise unit = +-8 counts, base noise 3 units (quality 97), ADC range 0 to 1023. DRIFT adds noise units per second since the fault was set. Sample period 10 ms. All marked "initial" in `lg_config.h` | Placeholders for the health model of Step 11. |
| 2026-11-20 | Plant time is real time, scenario time 0 is the start of `lg-plant`; a plant restart restarts the scenario. Plant on a default channel (inherits the sensor priority), sensors and gate on fixed-priority channels | A client of a plant is a higher-priority sensor, so inheritance helps; the sensors must keep their own priority when `cat` or `lgctl` talks to them. |
| 2026-11-20 | Own strict JSON parser in `core/` (no new dependency): milli-unit numbers with at most 3 decimals and 12 integer digits, no exponent, duplicate keys refused, depth 16, 1024 values, 8192 string bytes; config files are read at startup only | CLAUDE.md asks before a dependency is added. Strictness means a wrong file is refused with a reason, not guessed. |
| 2026-11-20 | `lgctl` exists now with the sensor subcommand only (`fault`, `fault-ro` as a test aid, `stats`); exit codes 2 usage, 3 invalid, 4 refused | Other subcommands arrive with their steps. |
| 2026-11-20 | `lg-sample-sink` is a stand-in for the controller (name `lg/controller`) and goes away or is replaced in Step 7 | Lets the stream, gaps and sample age be measured before the controller exists. |
| 2026-11-20 | Trace timing in `step06_sensors.sh`: a transition must lie inside the interval the trace brackets it with (rise between the last clear stamp and the first occupied stamp plus the largest round R of the trace, fall likewise), not in a fixed window | The plant time is read before the sensors in each round, so a reading is up to one round newer than its stamp. Fixed windows failed when the VM made a round 3 times longer. The largest round is printed and must stay under 1500 ms. |
| 2026-11-20 | `lg-sensor` has three kinds of thread: the main thread serves the device only (fixed-priority channel); the worker (SCHED_FIFO 45) does the periodic work and all `MsgSend` calls; two connector threads (RR 10) do `name_open` and `name_close`. State is shared under one mutex that is never held across a blocking call | Measured by hand on the VM (SIGSTOP of the controller): the first single-threaded version froze, first because `name_open` waits for the server, then because a server that has received a message and never replies keeps the sender blocked (`TimerTimeout` does not cover that phase when the channel has `_NTO_CHF_UNBLOCK`). Now only the worker can wait; the device always answers. Whether the ticks stop depends on whether the server had already received a message when it was stopped: in the recorded run the ticks continued (4692 to 4823 in 2 s), in a manual run they froze. The supervisor (Step 8) restarts a silent process. |
| 2026-11-20 | A `TimerTimeout` does not drop the connection; only an error that says the server is gone does | Dropping on every timeout cost a second of samples (reconnect period) for each hiccup. |
| 2026-11-20 | The sensor tick is a timer pulse on a channel created with `_NTO_CHF_PRIVATE | _NTO_CHF_FIXED_PRIORITY`, and the pulse carries the priority 45 explicitly (`LG_PRIO_SENSOR`) | Two measurements on the VM (`evidence/step06_channels.txt`): `SIGEV_PULSE_PRIO_INHERIT` runs the receiver at the priority the process was created with (10), so the first worker ran at 10 and so did the first jitter baseline; and without `_NTO_CHF_PRIVATE` another process can attach and fake a tick (found in the review, a claim of mine that it could not was wrong). The same explicit priority is used in `lg-plant` (its event timer) and `lg-jitter`. |
| 2026-11-20 | DRIFT noise = base noise + rate times elapsed seconds (capped at 100); it was rate times elapsed seconds | With the first formula the quality jumped from 97 to 100 when the fault was set, and a CUSUM in Step 11 would see an improvement first. |
| 2026-11-20 | `lgctl sensor ...` requires a parameter for noise, dropout, delay and drift and refuses one for the other modes | A forgotten value silently became noise 0 (a perfect sensor). |
| 2026-11-20 | The text of a sensor shows `seq=` of the sample on display and `tick=` of the latest tick | A stale sample (before a HANG or DROPOUT) must not look fresh. |
| 2026-11-20 | `lg_plant_events` takes signed window ends, the first window starts at -1 | An event at exactly t = 0 was never logged. |
| 2026-11-20 | `scripts/collect_evidence.sh <ip> [test...]` and `make evidence TESTS="..."` run only the named tests; a run replaces the evidence file of the test it runs | A full run overwrote the Step 5 evidence and left the numbers in the docs stale (found in the Step 6 review). |
| 2026-11-20 | `lg-jitter` (the bare timer on the same VM, in the same run, at a real priority of 45) is the reference for the sensor checks: the overruns of `west/a` must be at most 10 points above its late percentage, and the sequence gaps of every sensor at most its percentage of stalls of 20 ms or more plus 2 points; the largest sample age is reported, the average is asserted (under 2 ms) | Recorded run: the bare timer had 9 percent late gaps (over 12 ms), 11 of 1000 over 20 ms and a largest gap of 43249 microseconds, so the VM alone exceeds the README 10.3 limit of 20 ms for a sample age at times. The sensors in the same run: 8 percent overruns, 0 or 1 gaps in the stream phase. The limit is met or not depending on the host load; the evidence says what was measured. An earlier baseline (and the first worker) ran at priority 10 without anyone noticing; the numbers of that version were discarded. |
| 2026-11-20 | Plant restart replays the scenario from t = 0 (open consequence): a sensor reports a clear track for a train that disappeared, and the ground truth of the metrics resets. Step 8 will restart the plant automatically, which would hide this | Decide in Step 8: the plant takes an absolute start time so that it can continue, or a plant restart cancels the run. |
| 2026-11-20 | Open decisions for Step 7: (a) `lg_metrics_tick` needs the island ground truth while the controller must never see it (where does the metrics collector get it: the plant, over a separate path); (b) the island sensor of side S counts only axles of trains from S, so a failed `west/island` leaves west trains without an out-count while the east island sensor still sees the occupancy; (c) README 7.4 HANG means "stops sending heartbeats", here it stops the samples: heartbeats arrive in Step 8; (d) README 7.3 STATS mentions noise, the stats have counters only | Not needed for Step 6; each needs an answer before the controller depends on it. |
| 2026-11-20 | Open access gaps (Step 13): any process can register `lg/plant` or `lg/controller` (forged truth, eavesdropped samples) and can open the plant name and the sensor devices; fault injection needs a write-opened descriptor but no authentication | Same class as the gate gaps. |
| 2026-11-20 | Missed periods: when a tick starts two periods or more after the previous one, the skipped periods consume sequence numbers and are counted as overruns, and the pulses that queued up are discarded (`drain_pulses`) instead of replayed | A stall must show as a gap at the receiver, and a controller must never receive a burst of ticks after a stall (found in the review). |
| 2026-11-20 | The sensor stats carry `worker_policy` and `worker_priority`, read by the worker thread itself at each tick, and the target script checks them for all six sensors | The first check only read the priority of the device thread and could not have caught a worker at the wrong priority. |
| 2026-11-20 | `errno` is saved right after `MsgSend`, before any counter is touched; any error other than `ETIMEDOUT` is read as "the server is gone" and a controller that wants to refuse a sample must answer with `lg_ack_t.status`, not `MsgError` | Otherwise a timeout can be misread as a dead server, and a refusing controller would cause a reconnect and about 200 ms of lost samples each time. To be kept in mind for Step 7. |
