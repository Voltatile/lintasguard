# QNX evidence

Where QNX-specific features are used: file, function, why, evidence link. Updated whenever a QNX feature is added.

| Feature | File / function | Why | Evidence |
|---|---|---|---|
| Resource manager (`resmgr_attach`, `iofunc_func_init`, custom `io_read`) | `target/lg-gate/main.c`: `main`, `io_read` | The gate is an independent process with a file-like interface, inspectable from the shell | `evidence/step05_gate.txt`: `cat /dev/lg/gate` shows `state=DOWN ...`, then UP, LOWERING |
| Resource manager write refusal (`io_write` returns `EPERM`) | `target/lg-gate/main.c`: `io_write` | Nothing written to the device may move the gate (CLAUDE.md rule 4). The default QNX write handler silently accepts and discards the data, which was caught by the test and replaced | `evidence/step05_gate.txt`: `dd: /dev/lg/gate: write error: Operation not permitted`, gate unchanged |
| `devctl` (`__DIOT`, `__DIOF`, `_DEVCTL_DATA`, `iofunc_devctl_default`) | `target/include/lg_devctl.h`, `target/lg-gate/main.c`: `io_devctl` | Fault injection (SLOW, CRASH) and statistics through the device, without a second command path | `evidence/step05_gate.txt`: SLOW 150 percent gives `travel_ms=6005`; a factor below 100 percent is rejected (exit code 3); a fault through a read-only descriptor is refused (exit code 4); CRASH removes the process |
| Name service (`name_attach` on the resource manager dispatch, `name_open`) | `target/lg-gate/main.c`: `main`; `target/tools/lg-gate-test/main.c`: `do_cmd` | Clients find the gate by name, not by pid or channel id | `evidence/step05_gate.txt`: `/dev/name/local/lg/gate` exists while running and is gone after the crash |
| Message passing (`message_attach`, `MsgSend`, `MsgReply`, `MsgError`) | `target/lg-gate/main.c`: `on_gate_cmd`; `lg-gate-test`: `do_cmd`, `do_raw` | Synchronous, bounded command channel with an answer (the new state) or an error | `evidence/step05_gate.txt`: `reply: state=RAISING ...`; invalid command gives `EINVAL`, unknown type gives `ENOSYS` |
| Pulses (`pulse_attach`, `MsgSendPulse`) | `target/lg-gate/main.c`: `on_heartbeat`; `lg-gate-test`: `do_cmd` | Non-blocking liveness signal from the controller side | `evidence/step05_gate.txt`: gate stays UP for 3 s on heartbeats only; after the client is killed the gate trips and logs `no controller command or heartbeat for 109 ms (limit 100 ms)` (its own measurement) |
| Timer with pulse event (`timer_create`, `SIGEV_PULSE_INIT`, `timer_settime`, `message_connect`) | `target/lg-gate/main.c`: `start_tick_timer`, `on_tick` | A periodic 10 ms tick delivered into the same dispatch loop (jitter was not measured in Step 5) | `evidence/step05_gate.txt`: `ticks=724` in the devctl stats of the recorded run (uptime not recorded) |
| Watchdog in the gate (last line of defence) | `core/gate_model.c`: `lg_gate_model_step`; `target/lg-gate/main.c`: `on_tick` | If the controller goes silent the gate lowers by itself | `evidence/step05_gate.txt`: `kill -9` of the client, `watchdog_trips=1`, gate reaches DOWN; raise without heartbeats is undone |
| Real-time priority (`pthread_setschedparam` SCHED_FIFO 48) | `target/lg-gate/main.c`: `setup_priority` | The decision to lower must not wait behind lower-priority work | `evidence/step05_gate.txt`: `sched_policy=1 sched_priority=48` read back by the process through devctl stats |
| `_NTO_CHF_FIXED_PRIORITY` channel (measured priority behaviour) | `target/lg-gate/main.c`: `main` (`ChannelCreate`, `dispatch_create_channel`); `target/tools/lg-prio-demo/main.c` | On a default channel the server thread takes the priority of the sender, even a lower one, so a priority-10 client pulled a FIFO-48 server down to 10. The gate keeps its own priority whoever calls | `evidence/step05_priority.txt` (both cases, same VM, same program) |
| System logging (`slog2_register`, `slog2f`) | `target/lg-gate/main.c`: `setup_logging`, `logf_` | Durable, structured log of commands, state changes and watchdog trips | `evidence/step05_gate.txt`: `slog2info` excerpt (the buffer set shows as `lg_gate.<pid>`) |
| Process isolation and restart | `tests/target/step05_gate.sh` (crash injection block) | A crashed gate process leaves no stale state: name and device vanish, the restarted gate boots DOWN | `evidence/step05_gate.txt`: last four checks. Automatic restart by the supervisor is Step 8 |
