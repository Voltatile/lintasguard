# QNX evidence

Where QNX-specific features are used: file, function, why, evidence link. Updated whenever a QNX feature is added.

| Feature | File / function | Why | Evidence |
|---|---|---|---|
| Resource manager (`resmgr_attach`, `iofunc_func_init`, custom `io_read`) | `target/lg-gate/main.c`: `main`, `io_read` | The gate is an independent process with a file-like interface, inspectable from the shell | `evidence/step05_gate.txt`: `cat /dev/lg/gate` shows `state=DOWN ...`, then UP, LOWERING |
| Resource manager write refusal (`io_write` returns `EPERM`) | `target/lg-gate/main.c`: `io_write` | Nothing written to the device may move the gate (CLAUDE.md rule 4). | Name service (`name_attach` on the resource manager dispatch, `name_open`) | `target/lg-gate/main.c`: `main`; `target/tools/lg-gate-test/main.c`: `do_cmd` | Clients find the gate by name, not by pid or channel id | `evidence/step05_gate.txt`: `/dev/name/local/lg/gate` exists while running and is gone after the crash |

| Real-time priority (`pthread_setschedparam` SCHED_FIFO 48) | `target/lg-gate/main.c`: `setup_priority` | The decision to lower must not wait behind lower-priority work | `evidence/step05_gate.txt`: `sched_policy=1 sched_priority=48` read back by the process through devctl stats |
| `_NTO_CHF_FIXED_PRIORITY` channel (measured priority behaviour) | `target/lg-gate/main.c`: `main` (`ChannelCreate`, `dispatch_create_channel`); `target/tools/lg-prio-demo/main.c` | On a default channel the server thread takes the priority of the sender, even a lower one, so a priority-10 client pulled a FIFO-48 server down to 10. | Message passing sensor to plant (`MsgSend`, `LG_MSG_TRUTH_QUERY` / `LG_MSG_TRUTH_REPLY`) | `target/lg-sensor/main.c`: `query_plant`; `target/lg-plant/main.c`: `on_truth_query` | The sensors get the ground truth from a separate process; the plant runs at the priority of the sensor that asks (default channel, priority inheritance on purpose) | `evidence/step06_sensors.txt`: two trains pass and each sensor follows them |
| Message passing sensor to controller (`MsgSend`, reply `lg_ack_t`) | `target/lg-sensor/main.c`: `send_sample`; `target/tools/lg-sample-sink/main.c` | The controller stand-in measures the stream: sample count, sequence gaps, sample age | `evidence/step06_sensors.txt`: 986 to 1000 samples per sensor in 10 s, 0 or 1 sequence gaps, average age 25 to 78 microseconds, largest age 669 to 2053 microseconds |

| Periodic timer pulse (`timer_create`, `SIGEV_PULSE_INIT` with an explicit priority) on a channel with `_NTO_CHF_PRIVATE | _NTO_CHF_FIXED_PRIORITY` | `target/lg-sensor/main.c`: `worker`, `drain_pulses` | A steady sample rate; another process cannot attach to the channel and fake a tick; queued pulses are discarded instead of replayed | `evidence/step06_channels.txt` (explicit priority gives 45, `SIGEV_PULSE_PRIO_INHERIT` gives the process priority 10; another process cannot attach to a private channel) and `evidence/step06_sensors.txt` (`ticks`, `overruns`, `lg-jitter` baseline) |
| `TimerTimeout` on `MsgSend` (send phase) | `target/lg-sensor/main.c`: `bounded_send` | A server that is alive but not receiving costs one timeout per tick, not a freeze. The `timeouts=` counters in the final stats are 0, so the timeout path was not provoked deterministically |
| Fixed-priority channel and SCHED_FIFO 45 per sensor | `target/lg-sensor/main.c`: `main` | Reading a sensor from a low-priority tool must not lower the driver priority (see `evidence/step05_priority.txt`) | `evidence/step06_sensors.txt`: `sched_policy=1 sched_priority=45` for the device thread and `worker_policy=1 worker_priority=45` for the worker, read back by the threads themselves |
